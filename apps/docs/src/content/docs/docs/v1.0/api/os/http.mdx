# `http`

Install the required plugin:

```bash
tynd add http
```

```ts
import { http } from "@tynd/plugin-http/client";
```

HTTP/1.1 client with bundled TLS. For HTTP/2 or HTTP/3, use Bun's `fetch`.

## Methods

All return `Promise<HttpResponse<T>>` (except `download`).

### `get<T = string>(url, opts?): Promise<HttpResponse<T>>`

```ts
const { body, status, headers } = await http.get("https://example.com");
// body is a UTF-8 string
```

### `getJson<T = unknown>(url, opts?): Promise<HttpResponse<T>>`

```ts
const { body } = await http.getJson<Repo[]>("https://api.github.com/users/octocat/repos");
// body is typed as Repo[]
```

### `getBinary(url, opts?): Promise<HttpResponse<Uint8Array>>`

```ts
const { body: bytes } = await http.getBinary("https://example.com/image.png");
```

### `post<T = string>(url, opts?)` / `request<T = string>(url, opts?)`

Same shape as `get`. `request` lets you supply the method yourself, plus `responseType: "text" | "json" | "binary"` (default `"text"`); `"binary"` types the body as `Uint8Array`.

```ts
await http.post("https://api.example.com/events", {
  body: { name: "click" },
  headers: { authorization: "Bearer …" },
});

await http.request(url, { method: "OPTIONS" });
const { body } = await http.request(url, { method: "PUT", responseType: "binary" });
```

### `download(url, dest, opts?): Promise<{ path: string; bytes: number }>`

Streams the response body to disk. Good for multi-MB downloads — bytes never round-trip through JS memory.

The body is written to a temporary file next to `dest` and renamed into place only once it is complete, so a failed download never leaves a partial file or replaces an existing one. Unlike the request methods, a non-2xx status (redirects included, as `download` doesn't follow them) rejects with an error carrying the status (`HTTP status 404`) and leaves `dest` untouched.

```ts
const { path, bytes } = await http.download("https://.../big.zip", "./downloads/big.zip", {
  onProgress: ({ loaded, total }) => {
    const pct = total ? ((loaded / total) * 100).toFixed(1) : "?";
    console.log(`${pct}%`);
  },
});
```

## Options

```ts
interface HttpRequestOptions {
  method?:    "GET" | "POST" | "PUT" | "PATCH" | "DELETE" | "HEAD" | "OPTIONS";
  headers?:   Record<string, string>;
  body?:      string | Record<string, unknown> | unknown[];    // object → auto-JSON
  timeoutMs?: number;
  onProgress?: (p: HttpProgress) => void;
}

interface HttpProgress {
  phase:  "upload" | "download";
  loaded: number;
  total:  number | null;
}
```

`onProgress` fires during both upload (when `body` is set) and download. Throttled ~50 ms by the Rust side.

Download-specific options are a subset:

```ts
{ headers?, timeoutMs?, onProgress? }
```

`download` has no default overall deadline, so a large file can stream for as long as the server keeps sending. Without `timeoutMs`, only the connection (30 s) and idle time are bounded: a download fails when no byte arrives for 60 s (the TLS handshake and the first response included), and each received chunk restarts that clock, so a slow but steady transfer is never cut. With `timeoutMs`, it limits the whole call, body included; the 60 s idle limit still applies. Other requests keep a 60 s default overall timeout.

## `HttpResponse<T = string>`

```ts
interface HttpResponse<T> {
  status:     number;
  statusText: string;
  headers:    Record<string, string>;
  body:       T;
}
```

Non-2xx responses **don't throw** — inspect `status` yourself. (`download` is the exception: it rejects on a non-2xx status.)

Redirects are **never followed**: a 3xx comes back as the response, `Location` header included. Follow it yourself if you need to, so each hop goes through the `http` policy again.

## Notes

- **HTTP/1.1 only**. For h2 / h3, use Bun's `fetch`.
- Request and response bodies are capped at 100 MiB; `download` at 10 GiB.
- With a `security` policy, every URL is checked against its `http` rules (see [security](/docs/v1.0/api/os/security)); `download`'s `dest` goes through the `fs` scope.
- TLS is bundled — no OpenSSL runtime dep.
- Cookie jars are not managed by this plugin. Pass explicit cookie headers or keep session state in application code when required.
- Proxy: reads `HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY` env vars at startup.
