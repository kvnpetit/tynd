# API Reference

Every Tynd app has three surfaces:

- **Backend** (`@tynd/core`) — imported by `backend/main.ts`, exposes `app.start`, emitters, lifecycle hooks.
- **Frontend RPC** (`@tynd/core/client`) — typed proxy to your backend functions via `createBackend<typeof backend>()`.
- **Capability APIs** — the minimal core (app, current window and webview, os, path, monitors, security, log, workers) comes from `@tynd/core/client`; every other capability is an official plugin imported from its `@tynd/plugin-*/client` entry point.

<Aside type="note">
  **Availability follows configuration.** The host always carries the core; an API from a host-backed official plugin is compiled in, and works, once the plugin is declared in `plugins`. See [Bun runtime](/docs/v1.0/concepts/runtimes) and [Plugins](/docs/v1.0/api/plugins).
</Aside>

## Official plugins

Every plugin made by the Tynd team is an official plugin, installed with `tynd add <name>`.

### Host-backed plugins

Their native code ships in the Tynd host. Each one is a `@tynd/plugin-<name>` package imported from `@tynd/plugin-<name>/client`. `tynd add <name>` installs it and lists it in `plugins`; the next `tynd dev` or `tynd build` compiles it into the host.

## Web-platform APIs

`fetch`, `WebSocket`, `crypto`, `URL`, `Blob` and the other Web globals are not re-exported by `@tynd/core/client`: use the globals the WebView (frontend) or Bun (backend) provides. The plugin clients add the native paths the Web APIs lack, such as [`http`](/docs/v1.0/api/plugins/http) without CORS and [`compute`](/docs/v1.0/api/plugins/compute) hashing.
