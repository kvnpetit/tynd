# `wgpu`

`@tynd/plugin-wgpu` opens real OS windows backed by Metal, D3D12, Vulkan or GL that bypass the webview renderer, for apps that need direct GPU access (CAD viewers, game engines, scientific visualization).

<Aside type="caution">
  **Experimental.** Window lifecycle works; the render-command bridge is a stub. It is published to npm under the `experimental` dist-tag, not `latest`.
</Aside>

## Install

```bash
tynd add wgpu
```

or `bun add @tynd/plugin-wgpu` and list it in `tynd.config.ts`:

```ts title="tynd.config.ts"
export default {
  plugins: ["@tynd/plugin-wgpu"],
}
```

`tynd dev` and `tynd build` link the plugin's Rust crate into the app host they compile.

## Use

```ts
import { wgpu } from "@tynd/plugin-wgpu";

const probe = await wgpu.available();          // never throws
if (!probe.available) return useCanvasFallback(probe.reason);

const surface = await wgpu.createSurface({
  title: "CAD viewer", width: 1920, height: 1080,
  backend: "auto", powerPreference: "high-performance", presentMode: "fifo", format: "bgra8unorm",
});

const offError = surface.onError((message) => console.error(message));
await surface.resize(1280, 720);
await surface.close();
```

## Status

| Surface | Status |
|---|---|
| `wgpu.available()`, `createSurface()`, `list()` | Works |
| `WgpuSurface.resize()`, `close()`, `onResize` / `onClose` / `onError` | Works |
| `WgpuSurface.onFrame` | Fires only when the host is built with the `debug-frame-emit` Cargo feature |
| Adapter info, per-frame clear pass | Works |
| Render commands from JavaScript | Not present: `WgpuSurface` has no `submit` method yet |
| Three.js `render()` to native | Stub: logs a one-time warning and draws nothing; the native side only draws its clear pass |
| `wgpu.createCompute()` (headless) | Not present |
| `createSurface` on macOS and Linux (needs the main thread) | Rejected |

## API

| Export | Purpose |
|---|---|
| `wgpu.available()` | `{ available, backends, reason? }`; `false` without the `native` Cargo feature or with no working adapter |
| `wgpu.createSurface(opts?)` | Open a native window; returns a `WgpuSurface` with `id`, `width`, `height`, `backend`, `adapter` |
| `wgpu.list()` | Registry snapshot |

`createSurface` options: `title`, `width` (1280), `height` (720), `backend` (`"auto"`, `"vulkan"`, `"metal"`, `"dx12"`, `"gl"`), `powerPreference` (`"high-performance"` default, `"low-power"`), `presentMode` (`"fifo"`, `"mailbox"`, `"immediate"`), `format` (`"bgra8unorm"` default, `"rgba8unorm"`, `"rgba16float"`).

`WgpuSurface` events: `onResize(cb)`, `onClose(cb)`, `onError(cb)` (native render and device errors; repeated identical errors are throttled) and `onFrame(cb)` (see [Status](#status)). Each returns `{ dispose() }`.

## Three.js adapter

`@tynd/plugin-wgpu/three-adapter` exports `ThreeNativeRenderer`, a renderer shaped like the part of `THREE.WebGPURenderer` most apps use. It is a scaffold: `render()` does not encode the scene yet (see [Status](#status)).

```ts
import { wgpu } from "@tynd/plugin-wgpu";
import { ThreeNativeRenderer } from "@tynd/plugin-wgpu/three-adapter";

const surface = await wgpu.createSurface({ width: 1920, height: 1080 });
const renderer = new ThreeNativeRenderer(surface, { ownsSurface: true });
renderer.onResize((w, h) => { camera.aspect = w / h; camera.updateProjectionMatrix(); });
```

| Member | Effect |
|---|---|
| `new ThreeNativeRenderer(surface, { ownsSurface?, pixelRatio? })` | `ownsSurface` (default `true`) closes the surface on `dispose()`; `pixelRatio` defaults to `window.devicePixelRatio`, else 1 |
| `render(scene, camera)` | Stub: warns once, draws nothing |
| `setSize(width, height)` | Resizes the surface; a third `updateStyle` argument is ignored |
| `setPixelRatio(ratio)` | Sets `pixelRatio` |
| `onResize(cb)` | Native resize events; returns `{ dispose() }` |
| `dispose()` | Removes the listeners and closes an owned surface; also runs when the surface closes |
