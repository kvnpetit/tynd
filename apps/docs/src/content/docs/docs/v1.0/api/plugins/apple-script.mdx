# `apple-script`

`@tynd/plugin-apple-script` enables the host `apple-script` API and exposes its typed client. It has no separate core page; the whole API is described below.

## Install

```bash
tynd add apple-script
```

```ts
import { appleScript } from "@tynd/plugin-apple-script/client";
```

Declaring the plugin compiles the matching `api-apple-script` Cargo feature into the app host on the next `tynd dev` or `tynd build`. Or by hand: `bun add @tynd/plugin-apple-script` and list it in `plugins` in `tynd.config.ts`.

## `appleScript.run(script, language?)`

```ts
import { appleScript } from "@tynd/plugin-apple-script/client";

const { value } = await appleScript.run<string>('tell application "Finder" to get name of startup disk');
const jxa = await appleScript.run('Application("Finder").name()', "JXA");
```

| Argument | Type | Default | Notes |
|---|---|---|---|
| `script` | `string` | required | Source to compile and execute |
| `language` | `"AppleScript" \| "JavaScript" \| "JXA"` | `"AppleScript"` | `"JavaScript"` and `"JXA"` are the same engine |

Resolves with `{ value }`, the OSA result converted to JSON. Any other `language` is rejected.

## Notes

- macOS only. On other platforms the call fails with an `api_disabled` error.
- Compile and execute errors reject with `compile: ...` or `execute: ...` messages.
- With the ACL enabled, `appleScript:run` must be granted explicitly in your capabilities. Arbitrary script execution is the most powerful capability the host exposes; grant it only to windows that need it.
