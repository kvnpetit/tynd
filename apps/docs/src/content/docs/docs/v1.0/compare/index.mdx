# Comparisons

Tynd sits in the same category as Tauri, Wails, and Electron — a framework for shipping desktop apps with a WebView front. Each makes different tradeoffs on language, runtime packaging, and API surface.

## TL;DR

| | Browser runtime | Language choice | Native surface | Mobile | TS-native? |
|---|---|---|---|---|---|
| **Tynd** | System WebView | TypeScript/Bun | Broad OS APIs + official plugins | ❌ | ✅ |
| **Tauri v2** | System WebView | Rust + JS | Broad official/community plugin catalog | ✅ | ⚠ via bridge |
| **Wails v3** | System WebView | Go + JS | Go stdlib + bindings | ❌ | ⚠ via bridge |
| **Electron** | Bundled Chromium | Node.js + JS | Full Chromium + Node stdlib | ❌ | ⚠ via bridge |

<Aside type="note">
  **Headline:** Tynd is the only option where a TypeScript developer never writes Rust, Go, or Node glue. Same language end-to-end.
</Aside>

## Pick Tynd when

- You want **TypeScript end-to-end** — no Rust, Go, or Node glue.
- You prefer a TypeScript/Bun backend and native WebView over bundled Chromium.
- You want **zero-network IPC** and **zero-codegen typed RPC**.
- You want a **Bun TypeScript backend** with Node-compatible packages.

## Pick Tauri when

- You want a **more mature permission ecosystem** (more prebuilt resource-scope schemas and production examples).
- You need **mobile (iOS / Android)** support.
- You need a specific Tauri plugin from its broader ecosystem that Tynd does not cover, such as NFC or another mobile-focused integration. Tynd already has encrypted vault/keyring storage, declarative FS/HTTP scopes, and tray-aware window positioning.
- You're already a **Rust developer** who prefers writing Rust for the native layer.

## Pick Wails when

- You're a **Go developer** and want to reuse Go libraries on the native side.
- You need **GTK4 / WebKitGTK 6.0** on Linux (experimental but Wails-first).
- You want **custom IPC transports** or **server-mode** (run without a GUI).

## Pick Electron when

- You need **bundled Chromium** — consistent rendering across OSes, no WebView2 / WKWebView / WebKitGTK variance.
- You need **full Node stdlib** or the entire npm ecosystem in the main process.
- You need Electron's **`desktopCapturer`** MediaStream API, **`printToPDF`**, **Chrome extensions**, **Touch Bar** (macOS), or **StoreKit IAP**. Tynd has PNG screenshots and an official recording plugin, but not Electron's Chromium capture API.
- Binary size is not a concern.
