# Comparisons

Tynd sits in the same category as Tauri, Wails, and Electron — a framework for shipping desktop apps with a WebView front. Each makes different tradeoffs on language, runtime packaging, and API surface.

## TL;DR

| | Browser runtime | Language choice | Native surface | Mobile | TS-native? |
|---|---|---|---|---|---|
| **Tynd** | System WebView | TypeScript/Bun | Broad OS APIs + official plugins | ❌ | ✅ |
| **Tauri v2** | System WebView | Rust + JS | Broad official/community plugin catalog | ✅ | ⚠ via bridge |
| **Wails v3** | System WebView | Go + JS | Go stdlib + bindings | ❌ | ⚠ via bridge |
| **Electron** | Bundled Chromium | Node.js + JS | Full Chromium + Node stdlib | ❌ | ⚠ via bridge |

<Aside type="note">
  **Headline:** Tynd is the only option where a TypeScript developer never writes Rust, Go, or Node glue. Same language end-to-end.
</Aside>

## Pick Tynd when

- You want **TypeScript end-to-end** — no Rust, Go, or Node glue.
- You prefer a TypeScript/Bun backend and native WebView over bundled Chromium.
- You want **zero-network IPC** and **zero-codegen typed RPC**, with cancellation and `Channel` push built in.
- You want security that is deny-by-default for native commands: per-window/webview/origin capabilities, a default filesystem scope with protected locations, and runtime grants from the backend or a file dialog.

## Pick Tauri when

- You want a **more mature permission ecosystem** (more prebuilt resource-scope schemas and production examples).
- You need **mobile (iOS / Android)** support.
- You need a specific Tauri plugin from its broader ecosystem that Tynd does not cover, such as NFC or another mobile-focused integration.
- You need a **universal macOS binary** or **cross-compilation**.
- You're already a **Rust developer** who prefers writing Rust for the native layer.

## Pick Wails when

- You're a **Go developer** and want to reuse Go libraries on the native side.
- You need **GTK4 / WebKitGTK 6.0** on Linux (experimental but Wails-first).
- You want **server mode** (run without a GUI).

## Pick Electron when

- You need **bundled Chromium** — consistent rendering across OSes, no WebView2 / WKWebView / WebKitGTK variance.
- You need **full Node stdlib** or the entire npm ecosystem in the main process.
- You need Chromium-level hooks: `desktopCapturer` MediaStreams, **request interception** (`webRequest`), **permission-request handlers**, **download progress / cancel**, basic-auth and certificate handlers, **Chrome extensions**, **Touch Bar** (macOS) or **StoreKit IAP**.
- Binary size is not a concern.

| Updater | [Signed full and patch updates, channels, staged rollout](/docs/v1.0/api/os/updater) |

## What Tynd does not have

- **No mobile**, no **headless / server mode** (every app has a WebView window), no **universal macOS binary** and no **cross-compilation**: `tynd build` builds for the machine it runs on.
- **HTTP plugin is HTTP/1.1 only**; use Bun's `fetch` for HTTP/2 or HTTP/3.
- **No request interception**, no **basic-auth or TLS-certificate handlers**, no **runtime permission-request handler** (permissions are decided statically per webview), no **download progress, save dialog or cancel hooks** (start and result events only), no renderer sandbox option.
- **No Windows thumbnail toolbar** and **no tray balloon**.
- **No Chromium-specific APIs**: `desktopCapturer` MediaStreams, Chrome extensions, Touch Bar, StoreKit.
- **Per-OS rejections** — these calls reject instead of silently doing nothing:
  - Linux: `tray.attachWindow`, `tray.popUpContextMenu`, `setEffects`, `setAspectRatio`, `setMovable`, `getPrinters`, notification inline `reply`, clipboard RTF and custom formats, recent documents. Tray icons report no bounds and no hover events; renderer crashes are not reported.
  - macOS: `setAudioMuted` / `isAudioMuted`, silent `print`, `getPrinters`, notification `getDelivered` / `remove` / `removeAll`, per-window menu bars (one app-wide bar). `printToPdf` renders one continuous page and ignores layout options.
  - Windows-only: `setEnabled`, jump list, tray `onDoubleClick`. macOS-only: `app.dock.*`, `askForMediaAccess`, `titleBarStyle`, `appleScript`.
